# JX-Skills

沉淀个人**真正可复用**的 Skill 的仓库。

不求多，只求每个都经过实际场景验证、能反复拿来用。

## 收录标准

一个 Skill 想进这个仓库，至少要满足：

1. **真实用过** —— 至少在一个实际场景里跑通过，不是设想出来的
2. **边界清晰** —— 写清楚适用场景，也写清楚什么时候不该用
3. **可独立复现** —— 别人（或半年后的自己）拿到目录就能照着跑起来

不满足以上三条的，先放草稿区，验证后再转正。

## 分类

| 目录 | 分类 | 收录内容 |
| --- | --- | --- |
| `office/` | 办公 | Word / Excel / PPT、PDF、格式转换、批量文档处理 |
| `work/` | 工作 | 周报月报、会议纪要、任务拆解、项目与流程模板 |
| `dev/` | 开发 | 脚本工具、Git 工作流、环境配置、调试排查 |
| `data/` | 数据 | 数据清洗、表格处理、报表统计、可视化 |
| `media/` | 媒体 | 图片处理、音视频转码、批量重命名与整理 |
| `automation/` | 自动化 | 定时任务、批处理、系统操作、跨应用联动 |

新分类按需新增，目录名统一用小写英文，单词间用短横线连接。

## 目录结构

```
JX-Skills/
├── README.md
├── office/
│   └── <skill-name>/
│       ├── SKILL.md      # 用途、适用/不适用场景、使用方式
│       └── ...           # 配套脚本、模板、资源文件
├── work/
├── dev/
├── data/
├── media/
└── automation/
```

每个 Skill 一个目录，目录名用小写短横线命名（如 `office/pdf-split`）。

## SKILL.md 模板

```markdown
# <Skill 名称>

## 一句话说明
这个 Skill 解决什么问题。

## 适用场景
- ...

## 不适用场景
- ...

## 使用方式
1. ...

## 依赖
- ...

## 踩过的坑
- ...
```

## 添加流程

1. 在对应分类目录下新建 `<skill-name>/`
2. 按模板写 `SKILL.md`，目录里放配套脚本或模板
3. 本地验证一遍，确保能独立跑通
4. 提交：`git add . && git commit -m "add: <skill-name>" && git push`

## 维护约定

- 用不上的 Skill 果断删掉，不要囤积
- 每次重新使用后，把新踩的坑补回 `SKILL.md`
- 有依赖外部环境/版本的，在 `SKILL.md` 里注明版本范围
